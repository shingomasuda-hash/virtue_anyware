# 01. 要件整理 — VIRTUE Sales OS

## 1.1 事業ドメイン

株式会社VIRTUE（以下 VIRTUE / 本部）は、商業施設・催事会場で一般消費者向けに
電力会社／電気料金プランの切替営業を行う。VIRTUE は上位会社に対する一次代理店であり、
その配下に約20社（将来100社以上）の販売代理店が参加する。

```
上位会社（電力会社・取次元）
        │  受取単価 hq_unit_price
        ▼
     VIRTUE（一次代理店 / 本システムの運営主体）
        │  支払単価 agency_unit_price
        ▼
   販売代理店 A / B / C ...（約20社 → 将来100社以上）
        │
        ▼
   販売スタッフ（催事ブースで消費者へ営業）
        │
        ▼
   一般消費者（顧客）— 電力契約 → 太陽光 / 蓄電池へアップセル
```

## 1.2 システムの位置づけ

本システムは単なる CRM ではなく、以下を統合した VIRTUE の**基幹業務システム（Sales OS）**である。

| 領域 | 内容 |
| --- | --- |
| 販売管理 | 顧客・電力契約・契約ステータス・キャンセル |
| 代理店管理 | 代理店マスタ・代理店単価・代理店別実績・精算 |
| 催事管理 | 施設・催事・ブース・スタッフシフト・催事KPI |
| 経費管理 | 催事費・人件費・交通費・宿泊費・承認ワークフロー |
| 収益管理 | 売上・入金・支払・請求書 |
| 管理会計 | 月次損益・催事別PL・原価配賦・会計CSV |
| アップセルCRM | 架電・アポ・トスアップ・商談・成約 |
| データ分析 | 施設×ブース分析・曜日/時間帯分析・スタッフ分析・LTV |

## 1.3 最終ゴール（§38 / §82）

一人の顧客IDで以下を貫通して追跡できること。

```
催事 → ブース → スタッフ → 声掛け → 契約 → ワット数 → 本部売上
     → 代理店支払 → 粗利 → 催事経費 → 催事営業利益
     → アップセル架電 → アポ → トスアップ → 商談 → 成約 → 紹介売上 → 顧客LTV → 催事最終LTV利益
```

## 1.4 機能要件サマリ

### 認証・認可
- マルチテナント（organization 単位）
- 5ロール: `SUPER_ADMIN` / `HQ_ADMIN` / `HQ_STAFF` / `AGENCY_ADMIN` / `AGENCY_STAFF`
- 代理店ユーザーは **他代理店データへ一切アクセス不可**（サーバー側強制）
- 代理店ユーザーは **本部単価・本部売上・粗利へアクセス不可**（サーバー側でフィールド除去）

### マスタ
- 代理店マスタ（単価の適用期間付き履歴）
- 単価マスタ（本部受取 / 代理店支払を分離、コードへのハードコード禁止）
- 契約ステータスマスタ / アップセルステータスマスタ（追加編集可）
- 商材マスタ（電力以外へ拡張可能）
- 施設・催事・ブース・ブースタグ・スタッフ・給与単価
- 勘定科目・経費カテゴリ・取引先

### トランザクション
- 顧客 / 契約（1顧客に複数契約）
- 契約単価スナップショット（過去契約の金額は単価改定で変わらない）
- CSV取込バッチ / 行 / テンプレート
- アップセルリード / 架電履歴 / トスアップ
- 対応履歴（タイムライン）
- 経費 / 売上 / 入金 / 支払 / 請求書 / 精算
- 監査ログ

### 分析
- 本部ダッシュボード / 経営ダッシュボード / 代理店ダッシュボード
- 催事別PL・施設分析・ブース分析・曜日分析・時間帯分析・スタッフ分析
- アップセルファネル・催事ファネル
- LTV分析・キャッシュフロー・カスタムレポート

## 1.5 非機能要件

| 項目 | 方針 |
| --- | --- |
| セキュリティ | 認証・認可・CSRF・XSS・SQLi・セッション・レート制御・入力検証・監査ログ |
| 個人情報 | 電話/住所/生年月日は PII として扱い、アクセスを役割で制限・閲覧を監査 |
| パフォーマンス | 集計は DB 側で実施。fact/dimension を意識した索引設計 |
| レスポンシブ | PC 業務利用を最優先。タブレット/スマホでも閲覧可 |
| 拡張性 | 代理店100社以上・商材追加（ガス/通信/EV/リフォーム等）を前提 |
| 正確性 | 「分析画面の豪華さより元データの正しさ」を優先（§85） |
| 計算の一元化 | KPI・金額計算は `src/server/services` に集約し画面ごとの差異を作らない |
